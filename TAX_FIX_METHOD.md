# ZATCA Fix Method (v0.2.0)

## Important

Do **not** fix ZATCA rounding by changing VAT on an already submitted invoice just to force the stored grand total to match.

The application now corrects only the unsigned XML generated by RUKN, immediately before RUKN signs it.

### Example

ERPNext / RUKN source values:

- Net: `458.97`
- VAT: `68.85`
- Stored payable: `527.81`

UBL arithmetic requires:

- Tax inclusive: `458.97 + 68.85 = 527.82`
- Payable rounding: `527.81 - 527.82 = -0.01`
- Payable: `527.81`

So the XML should represent the 0.01 difference as `PayableRoundingAmount`, not by reducing VAT to `68.84`.

Likewise, line `RoundingAmount` is normalized from the exact two-decimal line net and line VAT values, and price `BaseAmount` is normalized from net price + allowance.
